## Decisions and facts captured

- Demo window with Axfood: two tentative slots, 10 Nov and 17 Nov 2026, 10:00–11:30 CET. 1.5 h total shared with
  Teradata AI Studio; Wisdom conversational-BI part gets 30–45 min. Everything must be sorted by 20 Nov.
- Next internal checkpoint: Friday 30 Oct 2026, same time, 30 min, second version of the demo with the Teradata team.
- Audience at Axfood: IT-driven. Platform managers, data & analytics architects, BI development managers, C-1
  (Teradata's direct contact). Next step after the demo would be a POC; Teradata hopes the demo is strong enough to
  shorten or skip it.
- Axfood landscape (Hadi): Teradata Vantage on AWS holds ~70–80 % of the data; SAP BW being decommissioned (Teradata
  proposing to bring it onto Teradata); a lake for raw data; MicroStrategy universes/cubes fed from Teradata and SAP BW.
  Goal: one common semantic layer humans and agents both use. Cost-aware ("AI where it makes sense"). Report changes
  today go through a long IT development cycle.
- Pär has an Axfood query log; Claude analysis of it surfaced one MicroStrategy report: campaign performance and
  forecast accuracy by chain and week. Axfood should recognise something they do in MicroStrategy today and see it
  done better, deeper and more agentic.
- Existing Nordmark demo shown (Live App, chat with Teradata federation, agent, domain context, extractor, evals,
  health). Question from Suresh: where did the competitor-opening fact come from (answer: structured data in the
  domain, web search possible via a skill). Hadi: it would resonate, but also show how it is built (connect a Teradata
  data mart with tables → context → outcome) because the audience is technical.
- Suresh (devil's advocate as the customer): do not ask them to export query logs; show Wisdom connecting directly
  to Teradata query logs (DBQL) and to MicroStrategy (or any BI tool) and pulling context automatically, with a
  human-in-the-loop approval. The message: "you just need a connection". Time-to-value must read as hours/days, not
  months.
- Talal: do not turn the demo around; outcome first (they cannot do this today), then how it is built, so the
  questions afterwards are "how fast can we build this, how soon can we involve the team".
- Pär: do not use Axfood naming (confusion, nitpicking). Mimic the report so they recognise themselves. Two
  priorities: the build part (semantic layer and context) and replacing a MicroStrategy report with more.
- Edvin: keep it synthetic; feed Pär's document into the demo builder; show query-log examples and possibly MCP to
  make the build feel automated; POC motion = 8 one-hour working sessions; Cisco story (domain in 2 weeks, 200
  users) as proof of speed.
- Branding: Teradata positions this as "Teradata Analyze, powered by WisdomAI", not a separate third-party product.
  Parked for Talal and Edvin (possible separate environment / URL for the Axfood session; POC environment TBD).
- Who presents: open; Talal leans toward the Wisdom experts presenting with Teradata hand-holding.
